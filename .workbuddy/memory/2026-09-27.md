- `shared/validation/primitives.ts`：只留 zod schema 构建函数

## 架构决策：不拍平 shared 包（已评估，结论=保留）

> ⚠️ **本节结论已作废（2026-09-27 晚）**：用户明确要求「忘掉之前的讨论，直接拆掉 monorepo」。已按用户决定执行拍平，见文末「拍平已执行」一节。**不要再引用本节的否决理由，也不要再向用户复述这段争论。** 下面内容仅作历史留档。

用户提出「不做子包、把类型直接拍平进 frontend，就不用 Model-Repo 架构」的替代方案。评估后否决，理由：

### 关键实证：`sideEffects: false` 救不了这个 bug
`git show HEAD:shared/package.json` 显示 `"sideEffects": false` **在修复前就存在**，zod 照样泄漏 89KB。这排除了「因为是 workspace 子包所以打包器保守」的假设 —— 泄漏与包边界无关，是 `export *` 聚合导出的传递闭包 + 模块级 `z.object()` 副作用共同造成的。**拍平进 frontend/src 只要仍写一个 `index.ts` 做 `export * from "./validation"`，会得到一模一样的 89KB。**

### 拍平的真实成本（实测）
- frontend 中对 `@my-app/shared` 的导入点：**91 处，分布在 68 个文件**（83 走根入口 + 8 走 `/validation`）
- shared 源码：**913 行**（types 661 + validation 232 + index 20）
- 还要删 `transpilePackages: ["@my-app/shared"]`、改 tsconfig paths 的 `@my-app/shared` / `@my-app/shared/*` 两条别名
- **性能收益：0 字节**（代码一行没少，zod 一行没少）
- 隐性损失：`shared` 不能 import `frontend` 这条物理边界消失，公共契约与内部实现会混在一起

### 结论与触发条件
保留子包。**当且仅当**以下任一条成立时再考虑拍平：① 确定未来 12 个月不会有第二个消费者（用户手上的 Electron + pnpm 项目若不复用这些类型）；② 出现在两个包里反复同步同一类型的情况；③ 该包开始需要独立构建流程（现在 `.ts` 直出、零 build 步骤，成本极低）。

### 正交提醒

### 拍平过程中踩到的坑（下次直接照做）
1. **`git mv <目录>` 在 Windows 上会失败**：`shared/node_modules` 里的 pnpm symlink 锁住了目录重命名（报 `Permission denied`）。解法：用 `git ls-files <dir>` 枚举 tracked 文件逐个 `git mv`，绕开 node_modules；未跟踪文件用普通 `mv`。
2. **`grep -rc` 会输出 0 计数的文件**，与 `git grep -c` 的口径不可直接 diff。做「改动前后逐文件计数比对」时必须 `| grep -v ':0$'` 过滤。
3. **短 specifier 会打破 Prettier**：`@my-app/shared` → `@shared` 变短后，原先折成多行的 `import type { ... }` 现在能塞进一行，Prettier 要求收回 —— Button.tsx / usePosts.ts / auth.controller.ts 三个文件因此新增格式告警。修法：对这几个文件跑 `prettier --write`。**教训：批量改 specifier 后必须重跑全量 format:check，不能只跑 tsc。**
4. 归类「是不是我引入的格式问题」的判定方法：`git show HEAD:<path> | prettier --stdin-filepath <path>` 与原文 diff，看 HEAD 版本本身是否已不合格 —— 这样能干净地区分历史遗留与本次引入。
