# 注释规范

> 本目录是全站注释的**唯一模板来源**。四份模板对应四种文件类型，本文件定义"何时写、何时不写、怎么写统一"。

## 模板索引

| 文件     | 适用场景                                               |
| -------- | ------------------------------------------------------ |
| `ts.md`  | 纯 TS 逻辑文件：工具函数、类型定义、类、Hook（非组件） |
| `tsx.md` | React 组件文件                                         |
| `vue.md` | Vue 3 组件文件（`<script setup lang="ts">`）           |
| `css.md` | 样式文件：设计令牌、组件样式                           |

## 一、何时必须写

1. **对外导出的任何东西**（组件、Hook、工具函数、类型、常量、类）必须有头注释——它们是公共 API，消费方只看签名和注释。
2. **魔法值必须注释**：数值字面量（`30 * 1000`）、哨兵字符串、位运算掩码。但优先让类型说话——能用枚举表达的不要靠注释映射表（见 ts.md 的 `AccountStatus`）。
3. **反直觉代码**：绕过框架默认行为的 workaround、为性能做的降级、依赖执行顺序的逻辑。
4. **公开函数的参数与返回值**：参数含义签名可自解释时 `@param` 描述可省，但返回值含义、边界情况（null / 空数组 / 抛异常）必须写。
5. **`@deprecated`**：必须带替代方案与移除版本，二者缺一不可。
6. **有条件的副作用**：`useEffect` / `watch` 必须写明"监听什么、何时触发、做什么"。

## 二、何时禁止写

1. **自解释代码不写**：`getUserById(id)`、`const isLoading = true` 这类签名即文档的，注释只降低信噪比。
2. **变更记录不写**：谁改的、什么时候改的、改了什么，一律走 git log。注释里维护变更记录必然过时。
3. **翻译式注释不写**：把代码逐行复述一遍（"调用 fetch 获取数据"）。
4. **TODO 散养禁止**：TODO 必须带负责人或 issue 号（`// TODO(huige): 接入后端接口后移除 #123`），无主 TODO 等于死代码。
5. **注释掉的死代码不留**：git 里有历史，删掉即可。

## 三、统一条款

### 文件头

- 每个文件必须有文件头注释，四个字段固定顺序：`@file` / `@description` 。
- `@file` 写实际文件名；`@description` 写"能力 + 使用限制"，不写实现细节。

### 函数

- 标签顺序固定：`@param` → `@returns` → `@throws` → `@example` → `@template`（如适用）→ `@deprecated`（如适用）。
- 泛型函数必须写 `@template` 说明类型参数的约束和用途。
- Hook 的对象返回值用列表式 `@returns` 逐项说明，不用一句话糊。
- `@warning` 是本团队自定义标签（非 JSDoc 标准，IDE 不渲染），只用于"传错参数会产生静默错误"级别的坑；普通注意事项并入 `@param` 描述。
- 异常约定写清边界：**抛异常**用 `@throws`；**返回 null 表示业务空**则写进 `@returns`，二者不要混。

### 类型 / 接口 / 类

- 接口头注释写"是什么"（数据来源、业务含义），字段注释写单行 `/** */`；多行只用于取值范围、单位、格式说明。
- 字段带单位的必须注明单位（时间戳注明 ms/s，尺寸注明 px/rem）。
- 可选字段的默认值写进注释（"默认 false"），与代码里的解构默认值互相印证。
- 类必须写 `@description` 说明职责边界；构造函数参数、公开方法按函数规则注释；`@template` 说明类型参数。
- 禁止用注释解释魔法数字的映射关系——改成枚举，让类型自己说话。

### 样式（详见 css.md）

- 设计令牌（颜色 / 阴影 / 动效时长）必须逐条注释用途；组件内禁止裸值。
- 有状态依赖的规则（hover / dark / 减动效）必须注明触发条件。

### 语言与符号

- 注释一律中文；专有名词、类型名、标签名保持英文原样。
- 块注释统一 `/** */`（JSDoc），行内注释统一 `//`，Vue template 内统一 `<!-- -->`，CSS 内统一 `/* */`。同一文件内不混用两套块注释风格。
- 占位符风格：模板中一律用具体示例值（如 `GoodsCard.tsx`、`formatDate`），不用"XX名称"这类抽象占位——复制后照着同结构的真实示例改，不容易填错。
